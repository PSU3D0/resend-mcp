## Migration Notes

No migration required for existing users. All changes are backward compatible additions that expand the API surface area.

### New Capabilities

1. **Email Listing**: Users can now retrieve paginated lists of emails using `GET /emails` with `limit`, `after`, and `before` query parameters.

2. **Broadcast Updates**: Broadcasts can now be updated via `PATCH /broadcasts/{id}` with fields like name, audience_id, segment_id, from, subject, reply_to, preview_text, html, and text.

3. **Segments**: Full CRUD operations for audience segments with filtering capabilities. Segments allow grouping contacts based on criteria.

4. **Topics**: Full CRUD operations for topics. Topics enable subscription-based preferences for contacts within an audience.

5. **Contact Properties**: Full CRUD operations for custom contact properties with support for string, number, boolean, and date types. Properties have optional descriptions.

6. **Contact-Segment Association**: APIs to add contacts to segments, list a contact's segments, and remove contacts from segments.

7. **Contact-Topic Subscriptions**: APIs to retrieve and update a contact's topic subscription preferences.

### Pagination

All list endpoints follow consistent pagination patterns using:
- `limit`: Number of items to return (1-100)
- `after`: Cursor for fetching items after this point
- `before`: Cursor for fetching items before this point

Responses include:
- `object`: "list"
- `has_more`: Boolean indicating more results
- `data`: Array of items
